# Codex network auto continuation (Go188 source)

This backend policy applies only to newly admitted, paired-device ordinary Bridge-owned Codex jobs. Existing failed/uncertain jobs and pre-upgrade queued jobs are never opted in. PM, delegation, controller, desktop, steer, voice and external-event flows keep their original behavior. The original user message is one logical queue item and retains its session actor until the logical terminal decision.

## Operator configuration and observation

Set `EVERYTHING_GO_CODEX_NETWORK_AUTOCONTINUE=true` and an exact comma-separated `EVERYTHING_GO_CODEX_NETWORK_AUTOCONTINUE_SESSIONS` allowlist for an isolated canary. After source/artifact/canary qualification, `EVERYTHING_GO_CODEX_NETWORK_AUTOCONTINUE_ALL_ORDINARY=true` enables all **new eligible ordinary jobs**, with the same per-run admission checks. This is operator policy, not a model-callable grant. Place `codex-network-autocontinue.disabled` in the existing data directory to prevent new automatic attempts; this does not interrupt an accepted native turn. Removing it enables subsequent eligible attempts only while original generation, lease and source still match; cancelled/paused unknown runs are not revived.

The existing authenticated WebSocket command `{"type":"request_status"}` returns `status_result.status.network_auto_continue`: actual configured/enabled/disabled mode, allowlist count, durable-store readiness, `clock_ready`/`clock_kind`, attempt/time bounds and verification limits. Use the original paired connection and credentials; do not create a caller or print tokens. `message_queue_snapshot.recovery[]` is optional, contains no principal/subject/paths, and keeps legacy queue/runtime enums: backoff is queued/queued; unknown reconciliation is queued/waiting_model. The original cancel action remains available for proven waiting attempts. Unknown active submissions require original native reconciliation rather than a fake cancellation.

## Durable execution boundary

Run, immutable input/hash, file leases, attempts and dispatch tombstones are committed in the original message_queue.sqlite transactions. A tombstone precedes each actual transport write. Exact `-32001 / Server overloaded; retry later.` before native acceptance permits byte-identical ingress retry. Valid failed/interrupted turn/start IDs count as accepted and must be reconciled. Partial writes, ACK loss, transport changes, unresolved native retry or unknown history never permit replay.

Accepted failed network/capacity turns can start a new linked continuation only on the same thread/model/effort/tier/sandbox/configuration, provider account subject and current source/principal. Complete explicit-full native turn history and exhaustive bounded item pagination must prove idle and no unresolved effects. Only user/agent/reasoning items currently establish coverage; command, MCP, dynamic/background/external or unknown items pause conservatively. Prompt text is not evidence of effect safety. New user input, writer handoff, revocation, closure or source ABA invalidate the generation; the final bounded transport write rechecks ownership after acquiring the actual transport mutex, without recursive native RPC or waiting for an inverted core mutex. After all durable/policy reads, local device/control/config/source/epoch snapshots are revalidated; the executor then rechecks its local account subject and exact owned native tuple and samples the core local predicate again, with no subsequent durable/native RPC read. Initial thread creation may consume only the single empty-to-owned-thread revision; it never rebases a retired source. Canonical full-turn items and paged items must match all fields, and latest exact failed parent is revalidated after pagination. Token refresh with the same stable account subject is allowed; missing account subject disables automatic recovery for that job and preserves the original single send. Explicit ordinary-usage denial blocks submission.

Five automatic retries share a 30-minute deadline beginning at the first recoverable native failure (including native retry wait), with 10/30/60/120/300-second delays and bounded 20% jitter. Typed retry-after may extend delay; arbitrary JSON-RPC data is not parsed as a retry hint. Two failed continuation rounds without verifiable progress pause. Shared cooldown/half-open lease keys contain authority/provider/model, never device or session. A dispatched, accepted or unknown recovery probe retains its scope until exact durable native settlement; elapsed lease time, restart or an unrelated initial send cannot retire it. Proven pre-writer contention durably defers the original retry without consuming an attempt or publishing native uncertainty; its original deadline and actor remain in force. Registered same-scope waiters use persistent original queue sequence FIFO; cancelled, superseded, failed, expired input-lease and deadline-expired rows cannot become ghost queue heads. Native completed is recorded separately from objective verification; this implementation does not infer a user objective or external side effect succeeded.

The first structured recoverable error is durably timestamped **before** canonical history reconciliation, so pagination/native retry waiting consumes the same deadline. Production admission requires a qualified Darwin continuous clock (`CLOCK_MONOTONIC_RAW`, including sleep) and cached kernel boot identity. The private run retains its admission wall/continuous anchor across Bridge restart; same-boot elapsed time cannot be extended by a wall rollback, while a wall jump forward may conservatively shorten the budget. Observed unqualified backwards time is durably locked out even after restart. Missing/changed boot or clock provenance pauses new recovery dispatch without completing, killing or replaying accepted/unknown native work. There is no wall-only platform fallback: a new job without this clock uses its original single send, and readiness reports recovery unavailable. No OS clock changes, sleep or reboot were performed in engineering tests; fake-clock/reopen tests qualify these guards, not native sleep behavior.

Input leases last at most 24 hours; all recovery input copies share a 256 MiB limit. Admission captures original upload session, manifest hash, byte hash and file identity; each writer rehashes against those frozen values. Waiting performs cheap guards, not repeated video hashing. Logical terminal + proven last rejected/accepted-terminal dispatch retires only the input copy in the same database; hashes, generations and all attempts/tombstones remain. Unknown, active, paused-uncertain or unresolved effects are retained even after lease expiry. Typed input pressure opts only the new job out of automatic recovery and leaves normal single-send admission available; other database errors remain failures.

## Engineering and native canary

Fake daemon/clock and real temporary SQLite tests exercise ingress rejection, accepted-terminal continuation, crash/ACK uncertainty, cancellation/ABA, attachment replacement, account changes, quota, scope sharing and storage failures. They never fabricate a provider failure as real native evidence.

`TestAutomaticNativeCanaryOneReadonlyTurn` skips by default. Root may execute it only after exact source/canary review, with `EVERYTHING_GO_RUN_NETWORK_NATIVE_CANARY=AUTHORIZED_ONCE`, a fresh empty absolute `NETWORK_NATIVE_CANARY_DIR`, and the original readonly subject hash in `NETWORK_NATIVE_CANARY_SUBJECT_SHA256`. It commits an O_EXCL original intent, uses a mode-0700 private CODEX_HOME with an exclusive mode-0600 copy of the original auth (never printed or included as evidence), then starts a private stdio app-server with an empty read-only workspace and local tool restrictions, and submits one fixed gpt-6.1-sol/medium turn. It qualifies normal native interoperability, not a live automatic-recovery Run; engineering faults exercise the actual recovery coordinator separately. The private auth is removed only after known terminal/private process cleanup. It does not modify the original CODEX_HOME/config/auth or shared daemon, send LINE/calls, force provider overload or retry. A failed/unknown canary is never replayed; inspect its original intent/native receipt. Real provider overload remains NOT_OBSERVED unless genuinely seen. Private process lifetime on a test-process failure is not an assurance that an accepted turn stopped; preserve original IDs and reconcile.

## Upgrade and rollback

The SQL schema additions are additive and legacy enum projections remain decodable, but Go187 does not understand multi-turn logical barriers or recovery tombstones. Returning to its signed artifact is **not a qualified semantic rollback**. Never restore the old database, delete evidence, stop accepted native work or automatically bootstrap an older binary after an uncertain cutover. Preserve the exact现场 and use Root-owned maintenance/forward repair with original native receipts. Production activation, signing/notary and real canary are separate Root-owned gates.
